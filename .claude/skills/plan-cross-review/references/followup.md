# 再レビューの手順の細部

SKILL.md の「再レビュー」の条件に当たったときに読む。実行フォルダを作るコマンドは SKILL.md の「再レビューの手順」にある。

### 確認のレビュー

1. 前回（1 回目）の実行フォルダを指定して、新しい実行フォルダを作る。要件と設計書は前回から写される。「再レビューは 1 回まで」と出たら上限なので、残る指摘をユーザーに伝える（示された作成済みのフォルダでまだレビューしていなければ、そのフォルダで続ける）。

   （SKILL.md の「再レビューの手順」にあるコマンドで作る）

2. 写された設計書を Read してから、直した節だけを Edit ツールで書き換える（読んでいないファイルの Edit は失敗する。全体を書き直すと、直していない節の言い回しまで差分に入る）。
3. 出力された「修正の一覧」のパスに、Write ツールで次を書く。レビュアーは、これと直した設計書で直しを確かめる。
   - **直したこと**: 前回の判断で採用した指摘ごとに、指摘の要約と、設計のどこをどう変えたか、その直しが影響するほかの節。「一部採用」は入れた部分を書く。採用した指摘のほかに変えたもの（ユーザーに頼まれて入れた見送りなど）も書く
   - **決定済み**: 「見送り」「不採用」「要確認」にした指摘と、一部採用で入れなかった部分を、1 行の理由とともに書く
   - 直した理由の弁解や、Claude が自信のない判断は書かない（レビュアーの注意を偏らせない）
4. SKILL.md の手順の 4. と同じく `prepare.sh` を実行する。`--cd` を省けば前回の作業フォルダを使う。前回の設計書からの差分も渡る。前回の実行フォルダが見つからないなどで失敗したら、`--followup` を付けずに新しい実行フォルダを作り、SKILL.md の手順の 2. から、確認のレビューの担当 1 体で設計書の全体をレビューする（前回の指摘や対応は書かない）。
5. SKILL.md の「レビュアーの決め方」で決めた確認のレビューの担当 1 体を、SKILL.md の手順の 4. と同じ呼び方で動かす。**終わるまで、設計書と読み先のコードを編集しない。**
6. SKILL.md の手順の 5. と同じく判断し、`decisions.md` の実行状態に「確認のレビュー（前回: <前回の実行フォルダ名>）」と書く。
7. 再レビューで採用した指摘（「未解決」とされた直しを含む）は、直し方が一通りに決まるものだけ設計に入れ、報告に「確認のレビューのあとの修正（未レビュー）」として挙げる。仕組みを足さないと直せないものは入れず、ユーザーに伝える。
8. SKILL.md の手順の 5. の形で報告する。「要件の充足」は「修正ごとの判定」（「解決」以外のものと、その扱い）に替え、件数の行は「比較なし」と書く。担当が結果を返さなかったら、報告に「直した部分は未確認」と書いて直したことの一覧を添える。

### ゼロからレビューし直すとき

選ぶ案か要件の解釈を変えたときは、`--followup` を付けずに新しい実行フォルダを作り、SKILL.md の手順の 2. から 1 回目と同じ担当でやり直す。要件と、変えたあとの設計書の全体を書き、前回の指摘や対応は書かない（先入観を渡さないため）。要件の解釈を変えたことは報告で伝える。この回で採用した指摘も、確認のレビューの 7. と同じ扱いにする。
