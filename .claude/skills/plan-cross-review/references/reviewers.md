# 担当の代わりと、利用枠を確かめられないとき

SKILL.md の「レビュアーの決め方」と手順 4. から、まれにしか通らない分岐を移したもの。担当が結果を返さなかったとき、利用枠を確かめられなかったときに読む。

## 代わりの担当

**代わり**: 担当が結果を返さなければ、原因を問わず、同じ側の軽い担当で 1 回だけ動かす（Astra → Sol、Fable → Opus）。1 体だけで動かす確認のレビューで Sol が結果を返さなければ、Opus で 1 回だけ動かす。Sol は Codex の担当、Opus は Claude の担当として数え、レビュー済みの担当を除くときも同じに扱う。

代わりの動かし方:

- 担当が結果を返さなければ、上の「代わりの担当」のとおり 1 回だけ動かす。Sol は同じ実行フォルダに `--model gpt-6.2-sol` を加えて `run_in_background: true` で、Opus は Agent ツールの指定を SKILL.md の手順 4. と同じにして `opus-reviewer` で動かす。Codex のやり直しは前のログを上書きするので、先に失敗の理由（エラーの要点）を控える。失敗の理由は SKILL.md の手順 5. で `decisions.md` の実行状態に書き、報告では代わりの担当の名前で書く。

## 利用枠を確かめられないとき

- ツールがない（ターミナルの Claude Code など）、呼び出しが失敗した・断られた、`plan.status` が `ok` でない、Fable の枠がないときは、利用枠を確かめられないとして Fable で動かす。この確認は担当を選ぶためだけに使い、結果によらずレビューと呼び出し元の作業を進める。
