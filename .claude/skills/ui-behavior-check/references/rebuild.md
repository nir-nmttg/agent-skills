# 作り直しの案

SKILL.md の「確かめられないとき」で作り直しの案を示すときと、それが選ばれたときに読む。

作り直しの案に書くもの:

- 実行するコマンド（プロジェクトの普段の起動方法: README・compose の定義から組む）
- 止まる・作り直されるコンテナと、いま動いているもの（`docker compose ps` などで確かめる）
- 接続先（SKILL.md の手順 2 の「開発環境を使ってよい」の判定を通っていること）と、DB に残る変更（起動で行われるマイグレーション・スキーマの同期・seed。わからないことはわからないと書く）
- コンテナの戻し方（worktree から起動するときは、確かめたあとメインの checkout から起動し直すコマンド）。DB に残った変更はコンテナを戻しても戻らないので、分けて書く
- 行わない操作: ボリュームの削除（`down -v` など）、DB の作り直し
- 同じフォルダでユーザーのサーバーが動いていたことが理由なら、作り直しの前に、ユーザーにそのサーバーを止めてもらう必要があること

「Claude が環境を作り直して確かめる」が選ばれたら、頼まれて使う扱いで進め、示したコマンドに限って、SKILL.md の手順 2 の「起動コマンドがコンテナを起動する」の例外にする。SKILL.md の手順 2 のほかの「起動しない」の条件（接続先が開発用でない、DB を作り直す・テーブルを削除するとわかっている、トンネルやリモートへの接続を含む）は例外にしない。示した範囲から増える操作が要るときは、SKILL.md の手順 2 の起動の確認に戻る。途中で失敗したら、示した戻し方でコンテナを戻し、適用済みの状態（マイグレーション・スキーマ）を確かめて、戻せなかったサービスと DB に残る変更を報告する。
