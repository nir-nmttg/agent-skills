# 再レビューの手順の細部

SKILL.md の「再レビュー」の条件に当たったときに読む。実行フォルダを作るコマンドは SKILL.md の「再レビューの手順」にある。

### 確認のレビュー

1. 前回（1 回目）の実行フォルダを指定して、新しい実行フォルダを作る。要件は前回から写される。「再レビューは 1 回まで」と出たら上限なので、残る指摘をユーザーに伝える（示された作成済みのフォルダでまだレビューしていなければ、そのフォルダで続ける）。

2. 出力された「修正の一覧」のパスに、Write ツールで次を書く。レビュアーは、これと前回からの差分で直しを確かめる。
   - **直したこと**: 前回の判断で採用して直した指摘ごとに、指摘の要約と、どう直したか（場所を添える）。「一部採用」は直した部分を書く。採用した指摘のほかに変えたもの（取り除いた要件にない変更、足したテスト、ユーザーに頼まれて直した見送り）も書く
   - **決定済み**: 「見送り」「不採用」「要確認」にした指摘と、一部採用で直さなかった部分を、1 行の理由とともに書く
   - 直した理由の弁解や、Claude が自信のない箇所は書かない（レビュアーの注意を偏らせない）
3. SKILL.md の手順の 4. と同じく `prepare.sh` を実行する。範囲の指定は渡さず、`--cd` を省けば前回のリポジトリを使う。前回のレビューのときの作業ツリーから今までの差分が、直したこととして渡る。「確認のレビューは使えない」と出たら（前回のスナップショットがない、rebase・マージを挟んだなど）、`--followup` を付けずに新しい実行フォルダを作り、SKILL.md の手順の 2. から、確認のレビューの担当 1 体で全体の差分をレビューする（前回の指摘や対応は書かない）。
4. SKILL.md の「レビュアーの決め方」で決めた確認のレビューの担当 1 体を、SKILL.md の手順の 4. と同じ呼び方で動かす。**終わるまでファイルを編集しない。**
5. SKILL.md の手順の 5. と同じく判断し、`decisions.md` の実行状態に「確認のレビュー（前回: <前回の実行フォルダ名>）」と書く。
6. 再レビューで採用した指摘（「未解決」とされた直しを含む）は、直し方が一通りに決まるものだけ直してテストし、報告に「確認のレビューのあとの修正（未レビュー）」として挙げる。仕組みを足さないと直せないものは直さず、ユーザーに伝える。
7. SKILL.md の手順の 7. の形で報告する。「要件の充足」は「修正ごとの判定」（「解決」以外のものと、その扱い）に替え、件数の行は「比較なし」と書く。担当が結果を返さなかったら、報告に「直した部分は未確認」と書いて直したことの一覧を添える（Haiku に書かせた直しなら、未レビューと明記し、完了を保留してユーザーに確認する）。

### ゼロからレビューし直すとき

作り方（選ぶ案）か要件の解釈を変えたときは、`--followup` を付けずに新しい実行フォルダを作り、SKILL.md の手順の 2. から 1 回目と同じ担当でやり直す。要件は今の解釈で書き、前回の指摘や対応は書かない（先入観を渡さないため）。要件の解釈を変えたことは報告で伝える。この回で採用した指摘も、確認のレビューの 6. と同じ扱いにする。
