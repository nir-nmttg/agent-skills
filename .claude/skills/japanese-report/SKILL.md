# 日本語で報告する

引数: $ARGUMENTS

報告が英語になる原因の多くは、サブエージェント・Codex・テストログ・英語のドキュメントなど、英語の材料に引きずられること。報告を書くときは材料の言語に関係なく、ここの書き方に従って日本語で書く。

## 呼び出され方ごとの動き

- **`/japanese-report` や「日本語で書き直して」と頼まれたとき**: 直前の報告（引数で範囲を指定されたらその部分）を、内容を変えずに日本語で書き直す。作業のやり直しや、新しい情報の追加はしない。
- **自分の判断で使うとき**: これから書く報告をこの書き方で書く。使ったことはユーザーに伝えなくてよい。

## 書き方

**日本語にするもの**

- 地の文はすべて日本語。英語の文を混ぜない。
- 見出し・ラベル・表のヘッダも日本語にする（`Summary` → 「まとめ」、`Changes` → 「変更点」、`Next steps` → 「次にやること」、`Status` → 「状態」、`Done` / `Not done` → 「完了」/「未完了」など）。
- ユーザーへの質問・確認・選択肢のボタン、`wrap_up` の recap も日本語にする。
- サブエージェント・Codex・ツールが英語で返した報告は、全文を貼らずに要点を日本語でまとめる。

**英語のまま残すもの**

- コードの識別子、ファイルパス、コマンド、設定キー、ブランチ名（バッククォートで囲む）
- エラーメッセージやログの原文（引用するときはコードブロックかバッククォートに入れ、意味がわかりにくければ日本語の説明を添える）
- 製品名・サービス名・モデル名（例: GitHub、Codex、Opus 5.5）
- 日本語の開発現場でもそのまま使う技術用語（例: commit、PR、branch、merge、diff、API）。無理にカタカナや訳語にしない

**読みやすさ**

- 結論を先に書き、簡潔にする。
- 翻訳調を避ける（「〜することができます」→「〜できます」、「〜が実行されました」→「〜を実行しました」）。
- 主語の「私は」は書かない。

## 対象外

コミットメッセージ、PR の本文、コードのコメント、ドキュメントなど、ファイルやリポジトリに残すものはリポジトリの慣習やユーザーの指示に従う（英語のリポジトリなら英語のまま）。このスキルが扱うのはユーザーへの報告だけ。

## 送る前の見直し

報告を出す前に、次が残っていないかを確かめ、あれば日本語に直す。

- 英語の文、英語の見出し・ラベル
- 英語のまま貼ったサブエージェントや Codex の報告
