# スキルを使う準備の確認

## 確認結果

!`bash "${CLAUDE_SKILL_DIR}/scripts/check.sh" 2>&1`

## 手順

1. 上の「確認結果」が空、またはエラーの場合は、Bash で `bash "${CLAUDE_SKILL_DIR}/scripts/check.sh"` を実行して取り直す。
2. 確認結果を**そのまま**ユーザーに表示する（ユーザーには確認結果が見えていないため、省略せず出力する）。表・対処方法の文言やコマンドは変えない。前置きや手順の説明は書かず、確認結果から始める。
3. すべて ✅（⚠️ だけ）なら、ここで終える。何も足さない。
4. 確認結果に「Claude が実行できるコマンド」があれば、それぞれのコマンドが何をするか（確認結果の箇条書き）を添えて、実行してよいかを 1 回だけ聞き、答えを待つ。コマンドは確認結果に書かれた 1 行だけにし、足したり変えたりしない。
   - 了承されたら、その 1 行を Bash で実行する（`brew install` は時間がかかるので、timeout を 600000 にする）。失敗したら、エラーの要点を伝える。
   - 実行したら `bash "${CLAUDE_SKILL_DIR}/scripts/check.sh"` で確認し直し、その結果をそのまま表示する。確認し直した結果にまた「Claude が実行できるコマンド」が出ても、もう一度は聞かず、残った ❌ を手順 5 のとおり案内する。
   - リンクのコマンドを実行し、確認し直した結果で `~/.claude/agents` へのリンクが ✅ になったら、サブエージェントは新しいセッションから使えると 1 行添える。
   - 断られたら、実行しない。
5. 残った ❌（ログイン・Homebrew・Xcode のコマンドラインツールなど、ブラウザやパスワードの入力が要るもの）は、ユーザーがターミナルで実行するよう、「対処方法」のコマンドを示して促す。最後に「実行したら、もう一度 `/skills-preflight` で確認してください」と 1 行で添える。
6. ログイン（`codex login`・`gh auth login`）はブラウザでの操作が要るので、自分では実行しない。
