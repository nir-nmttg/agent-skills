# 確認のレビューとゼロからのレビューの細部

SKILL.md の「再レビュー」の条件に当たったときに読む。実行フォルダを作るコマンドは SKILL.md の「確認のレビュー」にある。

## 確認のレビュー

1. 前回の実行フォルダを指定して、新しい実行フォルダを作る。決定事項は前回から写される。「再レビューは 1 回まで」と出たら上限なので、残る指摘をユーザーに伝える（示された作成済みのフォルダでまだレビューしていなければ、そのフォルダで続ける）。

2. 出力された「修正の一覧」のパスに、Write ツールで次を書く。
   - **直したこと**: 採用して直した指摘ごとに、指摘の要約と、どう直したか（場所を添える）
   - **決定済み**: 「要確認」「保留」「見送り」「不採用」にした指摘と、1 行の理由
   - 直した理由の弁解や、Claude が自信のない箇所は書かない
3. SKILL.md の手順の 4. と同じく `prepare.sh` を実行する。範囲の指定は渡さず、`--cd` を省けば前回のリポジトリを使う。前回のレビューのときの作業ツリーから今までの差分が、直したこととして渡る。「確認のレビューは使えない」と出たら（前回のスナップショットがない、rebase・マージを挟んだなど）、`--followup` を付けずに新しい実行フォルダを作り、SKILL.md の手順の 2. から Sol 1 体で全体の差分をレビューする（前回の指摘や対応は書かない）。
4. Sol 1 体を SKILL.md の手順の 4. と同じ呼び方で動かす。結果を返さなければ Opus 1 体で 1 回だけ動かす。どちらも結果を返さなければ、報告に「直した部分は未確認」と書く。**終わるまでファイルを編集しない。**
5. SKILL.md の手順の 5. と同じく判断し（判断の表は、この回も decisions.md に残す）、「修正ごとの判定」で「解決」以外とされたものも確かめる。直した部分に関わらない指摘は「見送り」にする。採用した指摘は、直し方が一通りに決まるものだけ直してテストし、報告に「確認のレビューのあとの修正（未確認）」として挙げる。

## ゼロからレビューし直すとき

作り方（選ぶ置き場所・仕組み）を変えたときは、`--followup` を付けずに新しい実行フォルダを作り、1 回目と同じく SKILL.md の手順の 2. から Sol と Opus でやり直す。決定事項は今の内容で書き、前回の指摘や対応は書かない（先入観を渡さないため）。この回で採用した指摘も、確認のレビューの 5. と同じ扱いにする。
