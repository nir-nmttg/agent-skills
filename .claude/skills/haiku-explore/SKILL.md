# Haiku 5.5 にコードの検索を任せる

引数: $ARGUMENTS

コードを広く探す作業を、読み取り専用の Haiku 5.5（推論レベル max）のサブエージェント `haiku-explorer` に任せ、Claude は結論と根拠の場所（`path:line`）だけを読む。Claude が `grep`・`sed`・`cat` で読んだ内容はすべて会話に残り、そのあとの毎回の応答で読み直されるので、探すために読んだ大量のコードが使用量を押し上げる。探す作業を任せれば、Claude の会話に残るのは結論だけになる。モデル・推論レベル・使えるツール（Read / Grep / Glob）はエージェントの定義で固定している。

## 任せるもの

答えが「場所・一覧・事実」で、Claude が次の判断に使うのが結論と `path:line` だけの調査を任せる。

| 種類 | 例 |
| --- | --- |
| 定義・使用箇所の洗い出し | 関数・型・設定キー・環境変数をどこで定義し、どこで使っているか |
| 既存の仕組みを探す | 似た実装・共通のヘルパー・既存の書き方（エラー処理、テストの形）があるか |
| 処理の流れの概略 | リクエストがどの層を通るか、ジョブがどこから起動されるか |
| 影響範囲 | ある変更が触れる呼び出し元・テスト・設定・文書 |
| 規約の把握 | ディレクトリ構成、命名、設定の置き場所 |

## Claude が自分で読むもの

- 場所がわかっていて、1〜2 ファイル（数百行まで）を読めば済む
- これから編集する箇所（Edit の前に正確な内容が要る）と、レビューで確かめる差分
- 設計の判断や原因のわからないバグの調査で、細部の理解が判断の根拠になる箇所。Haiku の報告で場所を絞り、決め手の箇所は Claude が読む
- 重要な決定（認証・認可・金額の計算・秘密情報の扱いなど）のコードが正しいかの判断
- ほかのスキルが Claude 自身に読むよう定めているもの（codebase-cleanup-workflow の共通の探索など）
- ユーザーが「自分で読んで」「Haiku は使わないで」と言っている

迷ったら任せる。

## いつ使うか

ユーザーに頼まれたときに加えて、頼まれていなくても積極的に使う。**Claude が場所の見当がつかないまま `grep`・`find`・`sed`・`cat` で探し始める前に、このスキルで Haiku に任せる。** 設計や実装の前の下調べ、plan-cross-review に出す設計の材料集め、haiku-implementation の指示書に書く関連ファイルの洗い出しにも使う。

**自分の判断で使うときの違い**

- 始める前に「〇〇の調査は Haiku 5.5 のサブエージェントに任せます」と 1 行だけ伝え、確認は待たずに進める。
- `haiku-explorer` が見つからない・エラーで結果が返らなかったときは、そのことを 1 行伝えて Claude が自分で調べる。

## 手順

### 1. 質問を書く

- 1 体に 1 つの質問を、具体的に書く（例: `PaymentService.refund を呼んでいる箇所をテストを含めてすべて`）。
- 「すべて」の洗い出しは、ディレクトリや観点ごとに小さく分けて、別々の Agent 呼び出しにする。答えの形は「1 件 1 行・説明は 1 文まで」を既定として質問に書く（報告が長いほど、Haiku の最後の生成に時間がかかる）。
- わかっていること（候補のファイル、名前、関係しそうなディレクトリ）と、欲しい答えの形（一覧・流れ・有無）を書くと速くなる。
- 互いに独立した質問は、**1 つのメッセージで複数の Agent 呼び出しにして同時に動かす**。1 体に大きな調査をまとめるより、小さく分けたほうが Haiku の会話が短く済み、速く安い（Haiku は会話が長くなるほど遅くなり、料金も上がる）。
- 対象が今のフォルダ以外のリポジトリなら（引数に `--cd <dir>` があるときを含む）、作業場所にそのリポジトリの絶対パスを書く。
- 秘密情報（トークン、パスワード、個人情報）は依頼に書かない。

### 2. Haiku に調べさせる

Agent ツールで呼ぶ。

- `subagent_type`: `haiku-explorer`
- `model` と `effort`: **渡さない**（定義の `claude-haiku-5-5` と `max` を使う。`model` に別名を渡すと固定が外れる）
- `prompt`: 次の形で書く

  ```text
  作業場所: <リポジトリの絶対パス>
  質問: <1. で書いた質問>
  わかっていること: <候補のファイルや名前。なければ省く>
  範囲: <探すディレクトリ。なければ省く>
  ```

- 終わると結果が届く。バックグラウンドで動いたときは、完了の通知を待つ間に、結果を使わない作業を進めてよい。

### 3. 報告を使う

- 結論と根拠の `path:line` をもとに次の作業を進め、Claude が読むのは必要な箇所だけにする。
- 編集する箇所は、編集の前に Claude が Read で確かめ、その内容をもとに Edit する。
- 確信度が「低」のとき、根拠が足りないときは、絞った質問を新しい `haiku-explorer` に聞き、報告の `path:line` を「わかっていること」に書く。1 体の会話を短く保つため。
- 「見つからなかった」を重要な判断（削除してよいか、ほかに呼び出し元がないか）の根拠にするときは、先に Claude が Grep で 1 回確かめる。

ユーザーには、結論が作業に関わるときだけ、Claude の言葉で短く伝える。
