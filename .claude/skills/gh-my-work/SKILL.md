# 自分宛ての仕事の一覧

## 取得結果

!`bash "${CLAUDE_SKILL_DIR}/scripts/my-work.sh" 2>&1`

## 手順

1. 上の「取得結果」が空、またはエラーの場合は、Bash で `bash "${CLAUDE_SKILL_DIR}/scripts/my-work.sh"` を実行して取り直す。
   - 未ログインのエラーなら `gh auth login` を案内して終了する。
2. 取得結果の表を**そのまま**ユーザーに表示する（ユーザーには取得結果が見えていないため、省略せず出力する）。
   - 表の列・並び順・リンク・ステータス表記は変えない。翻訳もしない。
   - ユーザーが特定の組織 / リポジトリ / 種類（レビュー依頼だけ、メンションだけ、Issue だけ等）を指定していれば、該当する組織見出し・表・行だけを残す。件数表記（冒頭の合計と組織見出しの件数）も絞った後の件数に直す。
   - リポジトリ列は同じリポジトリの先頭行にだけ入っている。絞り込みで先頭行が消えた場合は、残った行の先頭にリポジトリ名を補う。
3. 一覧の後に区切り線 `---` を入れ、`## ひとこと` として対応を検討すべきものを**最大 3 行**で挙げる。該当がなければこのセクションは省略する。優先度の目安:
   - 返信待ちのメンション: 基本的にすべて要対応（古いものから）
   - レビュー依頼: `🔁 再依頼` のもの、人が作った PR で依頼から 3 日以上たっているもの。bot（renovate / dependabot 等）の PR が溜まっていれば件数をまとめて触れる
   - 担当 PR: `✏️ 修正依頼` / `CI 🔴` / `⚠️ コンフリクト` があるもの（要対応）、`✅ 承認済` かつ `CI 🟢`（マージ可能）
   - 担当 Issue: 1 年以上更新がないもの（件数をまとめて「クローズかアサイン外しを検討」程度に）
4. 前置きや手順の説明は書かず、一覧から始める。

## ステータス表記

| 表記 | 意味 |
| --- | --- |
| 🔍 レビュー依頼 | 自分（または所属チーム）にレビューが依頼されている open な PR。「依頼」列は依頼された日時 |
| 💬 返信待ちのメンション | 直近 14 日に自分をメンションした投稿（本文・コメント・レビュー）のうち、その後に自分が投稿もリアクションもしていないもの。bot の投稿は除く。「メンション」列は最新の投稿で、複数あれば「ほか N 件」 |
| 👥 チーム名 | 個人ではなくチーム経由でレビューが依頼されている |
| 🔁 再依頼 | 一度レビューした後に、もう一度レビューが依頼されている |
| +N −M | PR の追加 / 削除行数 |
| ✅ 承認済 / ✏️ 修正依頼 / 👀 レビュー待ち | PR の reviewDecision |
| CI 🟢 / 🔴 / 🟡 | 最新コミットのチェック結果（成功 / 失敗 / 実行中） |
| ⚠️ コンフリクト | ベースブランチとコンフリクトしている |
| `ラベル` / 🎯 マイルストーン | Issue のラベル（最大 3 件）とマイルストーン |
