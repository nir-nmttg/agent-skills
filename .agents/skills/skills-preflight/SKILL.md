# Codex スキルを使う準備の確認

このリポジトリの `.agents/skills/` を対象に、実際の前提を確認する。Claude 側と同様に、確認だけを行い、インストール・ログイン・リンクの変更は別途依頼された場合に行う。

## 基本環境を確認する

1. このスキルからの相対パス `scripts/check.sh` を `bash` で実行する。対象プロジェクトの作業ディレクトリは変えず、スキルの実際の配置を基準にスクリプトのパスを解決する。
2. 出力にある各スキルの `SKILL.md` と、存在する `agents/openai.yaml` を読む。定義の存在と利用可能を区別し、フォルダ名と `name`、参照する補助ファイル、呼び出し設定、必要なコマンド・外部スキル・認証を確認する。スクリプトはファイルの存在・読み取りとリンクを確認するもので、YAML の構文や個別の依存関係は検証しない。
3. 実際に使うコマンドや認証だけを、存在確認・バージョン表示・ログイン状態の取得など読み取り専用の方法で確かめる。現在の Codex スキルには、Codex CLI・Claude CLI・GitHub CLI とそのログインを一律に要求しない。将来追加されたスキルは、その定義に基づいて確認項目を補う。

## 対象プロジェクトの前提を確認する

- 対象が指定されていればその場所、なければ現在のプロジェクトの指示、README、実行設定、CI から、利用するスキルに必要なランタイム・パッケージ管理・テストや文書検証の手段を確認する。対象が決まっていなければプロジェクト固有の前提は未確認とする。
- `docs-align-with-code` は対象文書と実装の参照、および既存の文書検証手段、2つのリファクタリングスキルは対象コードと影響範囲の検証環境、`test-suite-refactor` は対象テスト・実装・テスト実行環境を確認する。コマンドが見つかるだけで、依存パッケージやサービスまで準備済みと判定しない。
- 事前確認のために本体のスキル、テスト一式、ビルド、任意のセットアップスクリプトを実行しない。実行権限、ネットワーク、外部サービスなどで確認できない項目は、未導入・未ログインと断定せず未確認として残す。認証情報や設定ファイルの秘密値は表示しない。

## 結果を報告する

- 日本語で、スキルごとの「使える・条件付き・使えない・未確認」、根拠、不足と対処を表で示す。`skills-preflight` 自身は基本チェックが実行できれば使えると判断できる。他のスキルも、必須の前提を確かめた範囲で判断する。
- リンクは他のフォルダから使うための任意項目として扱う。同名の別ファイル・別の場所への有効なリンクは置き換えず、その状態を報告する。リンクの対処には、このリポジトリの `scripts/link-skills.sh --codex` を案内する。worktree ではメインの checkout から実行する必要がある。
- 不足への対処は対象の OS・プロジェクトで採用された方法に合わせて案内する。確認した範囲と未確認の前提を明記し、基本チェックだけで全スキルの実行成功を保証しない。
