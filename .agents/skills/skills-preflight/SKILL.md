# Codex スキルを使う準備の確認

このリポジトリの `.agents/skills/` を対象に、実際の前提を確認する。Claude 側と同様に、確認だけを行い、インストール・ログイン・リンクの変更は別途依頼された場合に行う。

## 基本環境を確認する

1. このスキルからの相対パス `scripts/check.sh` を `bash` で実行する。対象プロジェクトの作業ディレクトリは変えず、スキルの実際の配置を基準にスクリプトのパスを解決する。
2. 出力にある各スキルの `SKILL.md` と、存在する `agents/openai.yaml` を読む。定義の存在と利用可能を区別し、フォルダ名と `name`、参照する補助ファイル、呼び出し設定、必要なコマンド・外部スキル・認証を確認する。スクリプトはファイルの存在・読み取りとリンクを確認するもので、YAML の構文や個別の依存関係は検証しない。
3. 実際に使うコマンドや認証だけを、存在確認・バージョン表示・ログイン状態の取得など読み取り専用の方法で確かめる。現在の Codex スキルには、Codex CLI・Claude CLI・GitHub CLI とそのログインを一律に要求しない。将来追加されたスキルは、その定義に基づいて確認項目を補う。

## 対象プロジェクトの前提を確認する

- 対象が指定されていればその場所、なければ現在のプロジェクトの指示・README・実行設定・CI を静的に読み、利用スキルに必要な構成を確認する。対象未指定なら固有の前提は未確認とする。
- 整備スキルは対象文書・実装と影響範囲の既存検証手段を確認する。`codebase-cleanup-workflow` は組み合わせる5スキルの定義と前提を確認し、一部だけ実行可能なら範囲を示す。
- `minor-version-upgrade`・`major-version-upgrade` は静的確認で差分を反映する。両本体と `references/gate.md`・`verification.md` を読み、信頼済み Python 3.9 以降を絶対パス・`-I -S` で使え、公式情報・取得物・manifest/lockfile・全依存 inventory・根拠を確認できるか調べる。計画はモード指定不要、`execution` なし。`init` 直後に事前 `check` の機械検査結果を読み、6レビュー後に最終 `check` → `run` と進む手順を確認する。事前検査の unknown による非ゼロと、機械異常・結果未生成を区別できることを調べる。ゲートは対象コードを起動せず snapshot を保存する。
- 候補版と全新規配布物（image を含む）の最新の公式公開から7日以上を確認できることを調べる。7日未満・不明・未来は保留し、最新が新しすぎれば経過済みの適切な安定版を選ぶ。待機の短縮や override はなく、保留対象は再開可能日または不明の理由を報告できる手順を確認する。
- Ruby/Bundler、Node/npm・pnpm・Yarn、Python/uv・pip・Poetry 等の採用方式・版を、版指定・manifest・lockfile・CI から特定する。wrapper・Gemfile/gemspec・backend・plugin を版確認のために実行せず、採用していないツールや方式変更を要求しない。混在構成・直接/間接/build/platform 等の範囲を確認し、他言語へ更新範囲を広げない。
- 正しい候補と lockfile を対象コードの評価なしに作れるか確認する。`lockfile-only`・`dry-run`・`ignore-scripts` の名前だけで判断しない。解決・生成にコード評価が不可欠なら `references/isolation.md` の隔離が必要で、実行できない対象は条件付きとする。完成した候補の追加テストやブラウザの不足だけで更新全体を利用不可にしない。
- 全更新後依存とランタイムの既知情報を確認できるか調べる。監査 JSON の範囲・形式・鮮度と finding・エラー・skip・coverage の停止条件を読む。JSON 未収集の component は全依存版を公式告知/advisory DB へ照会して証拠化できるかも確認する。`advisories` の初回 `pass` に全公式/runtime/手動照会の最古の実取得時刻を `--observed-at` で固定し、全 `pass` の初回承認時刻と実取得時刻を24時間・未来日時で検査する手順も読む。同じ `pass` の再登録で期限を延長せず、調査結果・時刻の更新は新 RUN と全レビューに分ける。秘密・private 情報を無断送信しない。
- 必要な候補解決や任意検証に限り、既存 Docker CLI・daemon/context・固定 image・toolchain と helper を確認する。信頼済み CLI の読み取り専用接続確認は正規承認を利用でき、通常の拒否と承認後の結果を区別する。Docker 導入・daemon 起動・`sudo`・socket 権限変更は行わない。
- 反映前後の全適用予定パス・hash・実行 bit・削除を照合し、競合なら止め、元 bytes/逆差分から自分の更新分だけを安全に取り下げて新しい静的計画を確認する手順を読む。readonly snapshot の権限を反映先に使わず、静的確認と実行確認を区別する。
- 事前確認は読み取り専用に限る。更新本体、`new-run.sh`、`prepare`・probe・worker、image 取得・build、ゲート各工程、テストは起動しない。コマンドの存在・信頼済みツールの版・接続状態以外は推測で確認済みにせず、未導入・未ログインと権限不足を区別する。秘密値は表示しない。

## 結果を報告する

- 日本語で、スキルごとの「使える・条件付き・使えない・未確認」、根拠、不足と対処を表で示す。`skills-preflight` 自身は基本チェックが実行できれば使えると判断できる。他のスキルも、必須の前提を確かめた範囲で判断する。
- リンクは他のフォルダから使うための任意項目として扱う。同名の別ファイル・別の場所への有効なリンクは置き換えず、その状態を報告する。リンクの対処には、このリポジトリの `scripts/link-skills.sh --codex` を案内する。worktree ではメインの checkout から実行する必要がある。
- 不足への対処は対象の OS・プロジェクトで採用された方法に合わせて案内する。確認した範囲と未確認の前提を明記し、基本チェックだけで全スキルの実行成功を保証しない。
